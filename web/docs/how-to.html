How-to

Goal-oriented recipes for common operator tasks. Each recipe is independent: pick the one that matches what you're trying to do. If you're new, run through the Quickstart first so the commands feel familiar.

Add a public relay

So peers behind NAT can find each other when direct UDP punching fails. A relay is just a normal cluster node that happens to be publicly reachable.

  1. Provision a public Linux box

    Anywhere with a public IPv4 address and a UDP port reachable from outside (default 60611). A small VM is plenty.

  2. Bootstrap it from your admin node

    pln bootstrap ssh relay-eu=root@198.51.100.10 --admin bootstrapping relay-eu=root@198.51.100.10... relay-eu=root@198.51.100.10 ok

    --admin delegates admin authority too, so the relay can keep admitting peers if your root machine is offline. Use --publisher instead if the relay should be able to publish its own services or workloads but not admit peers, or drop both flags for a relay that only forwards traffic.

  3. Verify reachability

    pln status nodes PEERS NODE STATUS ADDR CPUs CPU MEM TUNNELS LATENCY IN OUT 7c9a4f8d (self) - - 8 2% 18% 1 - - - ab12cd34 direct (public) 198.51.100.10:60611 4 1% 8% 1 12ms 0 0

    The (public) tag means the cluster has verified the node is reachable from outside, not just hinted. New invite tokens minted from any admin will include this address as a bootstrap target.

Related: the mesh, pln bootstrap ssh, pln up --public.

Run with the root machine offline

So you can take your laptop with you. Delegate an admin grant to a node that stays online. A delegated admin grant carries no deadline, every node mints its own short-lived sessions locally with no round-trip to root, and grants renew automatically against any reachable delegating peer. The root machine can stay offline indefinitely.

  1. Pick the node that should hold admin

    A relay is a natural fit (always-on and well-connected). Note its peer ID:

    pln status nodes --wide PEERS NODE STATUS ADDR 7c9a4f8d3e2b1c5a6d8e9f0a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8091a2 (self) - - ab12cd34e5f6789a1b2c3d4e5f6789a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7 direct (public) 198.51.100.10:60611

  2. Grant admin to that peer

    pln grant ab12cd34 --admin grant issued (admin) to ab12cd34

    The --admin tier lets the peer issue further grants and admit new peers without involving root. An admin grant has no deadline, so it never needs renewing and never expires while the peer stays in the cluster.

  3. Confirm and shut root down

    pln down

    The cluster keeps running. Each node proves its own liveness with locally minted sessions, so admission carries on with root offline. Issue invites, grant new peers, and seed workloads from the relay using a context (see below).

  4. Verify with root down

    From the relay, the cluster reports healthy and admits work while the root machine is off:

    pln status HEALTHY ADMIN SEEDS NAME HASH STATUS REPLICAS LOCAL UPTIME greeter 3a8c7d2e running 2/2 * 14m pln context show context: default dir: /var/lib/pln identity: 4e9b1c77 issuer: 7c9a4f02 status: ok not before: 12 May 2026 09:14 BST rejoin by: never (admin grant) caps: delegate=true admit=true publish=true max_depth=3

    rejoin by: never (admin grant) confirms the admin grant has no deadline. A delegated leaf or publisher grant would instead show a rejoin by: date that the daemon keeps fresh on its own.

Bake the tier in at join time. If you're standing up a fresh relay, skip the post-hoc grant: pln bootstrap ssh root@host --admin or pln invite --admin --subject <peer-pub> mints the relay with admin authority from the start. Use --publisher for a relay that should publish but not delegate.

Related: Sessions, pln grant, pln invite.

Restrict who can call a workload or service

Bake properties into the callers' grants and attach --allow-prop clauses to the published resource. The policy clause rides on the resource itself; the caller's grant properties are checked at the admission authorise stage on every call. See Admission for the model.

  1. Tag the callers

    For peers that already exist:

    pln grant ab12cd34 --prop role=lead --prop team=backend grant issued (leaf) to ab12cd34

    For new peers, bake at join time:

    pln invite --prop role=lead --prop team=backend

  2. Publish the resource with policy

    pln serve 8080 internal-api --allow-prop team=backend pln seed ./hello.wasm greeter --allow-prop role=lead

    Repeat --allow-prop for additional clauses; all must match (conjunction).

  3. Verify denials are opaque

    Try to call the resource from a peer whose grant doesn't carry the required property. The authorise check fails and the call is reported as not found rather than as a distinct denial; this prevents an unauthorised caller probing for which workloads exist.

    pln call greeter run 'hi' Error: no such workload

Need disjunction? Mint both groups with a shared property and require it on the resource:

pln grant <editor> --prop tier=privileged
pln grant <admin>  --prop tier=privileged
pln serve 8080 ops --allow-prop tier=privileged

Pollen pushes disjunction up to the issuance side so the authorise check stays a trivially fast property match. The property name itself is your conceptual group.

Related: Admission, pln serve, pln seed.

Publish a static site across the cluster

Every node with static-http enabled claims the site and serves it locally; requests are routed by Host header.

  1. Enable the static HTTP listener on each node that should serve

    pln set static-http set static-http=:8080 (run `pln restart` to apply) pln restart

    Pass a port to override: pln set static-http :9000. Run on every node you want to serve from.

  2. Publish the directory from any publisher or admin node

    pln seed ./public my-site seeded my-site (12 files, manifest 3a8c7d2e)

    pln seed hashes every file into the local content store, signs a static-site spec, and gossips both. Each enabled node pulls the missing blobs and starts serving.

  3. Confirm rollout

    pln status static STATIC NAME MANIFEST REPLICAS LOCAL PUBLISHER my-site 3a8c7d2e 3/3 * 7c9a4f8d curl -H "Host: my-site" http://localhost:8080/

    3/3 means three replicas claimed against three eligible nodes. Re-running pln seed ./public my-site is idempotent: the spec gets a fresh manifest, old blobs are GC'd once nothing references them. The site keeps serving after the publishing node leaves; the spec lives in cluster state until it is unseeded, while the publishing grant is within its deadline and not revoked.

Related: Storage, pln seed, pln set static-http.

Pin a workload's placement

Pollen places replicas based on local scoring. You can tilt the scoring with flags, or override it for special cases.

Run a single replica everywhere

Use when every node should hold a copy (PDPs, edge caches, agents):

pln seed ./agent.wasm --everywhere

Set a higher target replica count

Use when you want headroom across the cluster. Default is two:

pln seed ./api.wasm --min-replicas 5

Restrict by property

Tag the eligible nodes, then require the tag on the spec. The capability gate stops other nodes from claiming the spec at all:

pln grant <node> --prop region=eu pln grant <node> --prop region=eu pln seed ./eu-only.wasm --allow-prop region=eu

Strictly, --allow-prop gates callers at the admission authorise check, not placement. To restrict placement specifically you'd match host-side properties; the simplest approach for now is property-tagging the nodes you want to host and gating the resource so only they can act on it.

Related: Workloads, pln seed.

Recover a context that can't connect

A delegated grant has a single hard deadline (default 30 days). The daemon renews it automatically against any reachable delegating peer, and a wire-mode context renews opportunistically on the next pln call. If the machine was offline past the deadline, renewal is no longer possible and the context must rejoin with a fresh invite.

  1. Read the precise cause

    The refused command already names it. Confirm with the context's own state:

    pln context show context: staging target: root@staging.example.com dir: ~/.pln/contexts/staging identity: ab12cd34 issuer: 7c9a4f02 status: expired not before: 14 May 2026 09:14 BST rejoin by: 13 Jun 2026 18:25 BST caps: delegate=false admit=false publish=true max_depth=0

    status: reads expired once the deadline has passed, or revoked if the identity was denied. There is no degraded here: a still-valid grant whose automatic renewal is failing shows as DEGRADED node health in pln status, not in context show. Reconnect that node to any delegating peer and renewal resumes on its own. Only expired or revoked needs the steps below.

  2. Mint a fresh token on the cluster

    Invites are signed on the node, so mint over SSH against an edge node:

    ssh root@edge.example.com pln invite --ttl 24h eyJ0b2tlbiI6...

  3. Rejoin the existing context

    Redeem the token into the same context name; this replaces the dead identity in place:

    pln --context staging join eyJ0b2tlbiI6...

  4. Verify

    pln --context staging status HEALTHY PUBLISHER pln --context staging context show context: staging target: root@staging.example.com dir: ~/.pln/contexts/staging identity: ab12cd34 issuer: 7c9a4f02 status: ok not before: 17 May 2026 14:25 BST rejoin by: 16 Jun 2026 14:25 BST caps: delegate=false admit=false publish=true max_depth=0

    The status header prints instead of a connection error, and context show reports status: ok with a fresh rejoin by: deadline the daemon will keep renewing on its own.

Related: Sessions, pln ctx show, access expired or node degraded.

Export a blob's contents to a local file

Blobs are encrypted at rest, so reading one from the on-disk store is not possible directly. pln fetch is the export path: it streams plaintext bytes from any node holding the blob and writes them to the file you choose. The publisher need not be online; a blob keeps serving from its holders while the publishing grant is within its deadline and not revoked.

  1. Pick the destination

    The second positional argument is the destination. Use a file path to write to disk, or - to write to stdout (handy for piping into tar, jq, file, and so on).

    pln fetch payload ./payload.bin wrote 9f2b1c4d to ./payload.bin

  2. Verify

    Hash the file locally; it must match the blob's content address.

    shasum -a 256 ./payload.bin

The local content store is not modified by fetch. If you want this node to also host the blob, use pln seed separately.

Related: Storage, pln fetch.

Manage multiple clusters from one shell

Contexts let you point your CLI at different daemons without re-typing flags. The reserved name default always resolves to the local daemon at $PLN_DIR.

  1. Add a context for the remote cluster

    pln ctx add prod root@prod.example.com --from default

    Targets containing @ bind to a remote daemon over SSH. --from default imports your local admin keypair so this shell can act as admin against the remote cluster.

  2. Switch active context

    pln ctx use prod pln status # now reads prod

    Override per-command via $PLN_CONTEXT=prod pln status, or skip contexts entirely with -H root@prod.example.com pln status.

  3. Switch back

    pln ctx use default

Local-only contexts. Targets that are absolute paths bind to a local pln dir, useful for running multiple test clusters on one machine. Each gets its own UDP port assigned automatically so they coexist with the default context.

Related: pln ctx.

Rotate a node's properties

Properties are baked into a peer's grant, so a rotation means re-issuing the grant. The flow differs for delegated peers and the root.

Delegated peer

Re-issue with pln grant. The new grant supersedes the old one and gossips out:

pln grant ab12cd34 --prop role=primary --prop region=eu grant issued (leaf) to ab12cd34

Root node

Root issues its own grant from config.yaml, so update the persisted properties and let the next pln up re-issue:

pln props role=primary region=eu properties updated (run `pln restart` to apply) pln restart

Replace semantics: positional args define the complete set, so any unlisted key is removed. Use pln props --clear to wipe.

Related: Admission, pln props, pln grant.

Cap what a tenant can publish

Bound a tenant's footprint by setting count budgets on its grant. Budgets are count-only: a maximum number of functions, blobs, and sites. There are no byte or traffic quotas. The accounting plane enforces the cap at the admission account stage on every write the tenant makes.

  1. Issue the grant with budgets

    pln grant ab12cd34 --publisher --max-functions 10 --max-blobs 50 --max-sites 2 grant issued (publisher) to ab12cd34

    Each flag takes a uint32 and defaults to 0. Re-issue with pln grant to raise or lower a limit; the new grant supersedes the old one and gossips out. The same --max-* flags are accepted by pln invite, so a tenant can be capped at enrolment rather than after the fact.

  2. Verify the cap holds

    From the tenant, publish past the limit. The write is refused and the admission reason is on the CLI:

    pln seed ./extra.wasm overflow Error: admission: functions budget exhausted: authority holds 10, limit 10

    The kind token is plural (functions, blobs or sites); a blob or site over its cap is refused the same way with its own token. Existing resources keep serving; only the write that would exceed the cap is refused. See budget exhausted.

Related: Admission, pln grant, budget exhausted.

Revoke a peer

Tear down a peer's connections and put it on the deny set so it can't rejoin without a fresh grant.

  1. Identify the peer

    pln status nodes

  2. Deny it

    pln deny ab12cd34 denied peer ab12cd34

    Deny is chain-aware. The deny gossips out and, on the next admission check, every node invalidates the denied peer's whole subtree and everything it published, cluster-wide. Every node also tears down its tunnels to the denied peer.

  3. Verify

    pln status nodes offline peers: 1 (use --include-offline)

Cascading revocation. If the denied peer had issued grants to others, those grants chain through it and become invalid too, and any workloads, blobs, or sites the subtree published stop being admitted. pln status nodes --include-offline shows the affected peers.

Related: pln deny, Admission.

Upgrade across the cluster

There is no rolling-upgrade orchestration. Run pln upgrade --restart on each machine independently.

pln upgrade --restart

Wraps Homebrew on macOS and the install script on Linux (preserving install method). --restart bounces the background service so the new binary picks up.

Related: pln upgrade.

Run a public edge for tenant share URLs

Pollen Cloud-style deployments expose three operator-controlled listeners on each edge so anyone with a token, a tenant's pubkey, or a published site name can reach the cluster from the open internet.

  1. Enable the three listeners

    pln set control-tls :7443 # tenant CLIs dial here over mTLS pln set static-http :8080 # static-site serving pln set static-http-domain pln.sh # enables <name>-<slug>.<domain> routing pln set gateway :8088 # anonymous blob/fn redemption pln restart

    All three are plain HTTP (or TLS+mTLS in the case of control-tls); a TLS-terminating proxy in front handles public certs.

  2. Point DNS at the edge

    Three DNS records resolve to the edge node's public IP. Front them with Cloudflare orange-cloud (or any TLS terminator) so browsers see valid certs; the mTLS endpoint on :7443 goes through grey-cloud / direct A records. Cloudflare can't proxy custom-protocol mTLS where the client cert is the auth.

    • blob.pln.sh → edge IP, proxied, origin edge:8088
    • fn.pln.sh → edge IP, proxied, origin edge:8088
    • *.pln.sh (wildcard) → edge IP, proxied, origin edge:8080; serves pln seed'd sites at <name>-<slug>.pln.sh where the slug is the 12-char base32 of SHA-256 of the publisher's pubkey
    • edge.pln.sh:7443 → edge IP, direct (grey cloud / non-Cloudflare); wire-mode CLI mTLS endpoint

    Top-level subdomains blob, fn, and any future system names are reserved. The static handler only matches Hosts that parse as <name>-<slug>.<domain>, so a tenant who publishes a site called blob lands at blob-k7r4z9xa8n2p.pln.sh and can't shadow blob.pln.sh.

  3. Tenants join the cluster over the wire

    pln context add cloud pln://edge.pln.sh:7443 pln context use cloud pln join <token> # token from `pln invite` on an admin node

    Wire-mode contexts skip admin-key generation; identity is minted at pln join time against the token's cluster claim. No local daemon required. Every subsequent pln command dials the edge over mTLS-QUIC.

  4. Verify the loop end-to-end

    pln seed ./photo.png # blob (token-only) pln share photo.png https://blob.pln.sh/_/RrkFG...AAAA curl -sf https://blob.pln.sh/_/RrkFG...AAAA > out.png pln seed ./echo.wasm --public # workload (anonymous) seeded echo (3a8c7d2e) → https://fn.pln.sh/k7r4z9xa8n2p/echo curl -sf https://fn.pln.sh/k7r4z9xa8n2p/echo -d 'hello' pln seed ./dist mysite # static site pln status sites NAME MANIFEST REPLICAS LOCAL PUBLISHER URL mysite 3a8c7d2e 1/1 ab12cd34 https://mysite-k7r4z9xa8n2p.pln.sh curl -sf https://mysite-k7r4z9xa8n2p.pln.sh/

Infra is out of scope. The Terraform that provisions the edge node, registers DNS, and configures Cloudflare lives outside this repo. Update it alongside any change to listener ports or DNS shape; the pln binary alone can't reconfigure your zone.

Related: pln set, pln share, pln context add, Admission.
